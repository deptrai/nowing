# Story 3.14 Acceptance Audit — Memory Injection (Bounded Retrieval)

- **Spec:** `implementation-artifacts/3-14-memory-injection-bounded-retrieval.md`
- **Diff:** `implementation-artifacts/3-14-in-review.diff`
- **Evidence artifact:** `implementation-artifacts/evidence/3-14-memory-performance.json`

## Verdict summary

The code changes implement the bounded-retrieval contract (AC-1, D1–D10) and the 1.0/1.1 schema gating (D9) across the backend, MCP server, web builder, and agent prompts. The main blocker is the required AC-3 latency evidence artifact: it is stale and does not match the final benchmark script. A few small `patch` items remain. AC-5 live freshness is intentionally deferred and documented.

## Findings

### reject

- **The AC-3 performance evidence artifact is stale and was generated by an earlier version of the benchmark script.**
  - `evidence/3-14-memory-performance.json` still uses the pre-B16 `s314probe` probe keyword in its `queries` block (`3-14-memory-performance.json:24`, `:27`, etc.), while the current `scripts/benchmark_memory_story_3_14.py` emits `s314bucket{q:02d}` with disjoint subject phrases (`nowing_backend/scripts/benchmark_memory_story_3_14.py:266-271`).
  - The artifact lacks the `environment` block, `generator_script_hash`, `uv_lock_hash`, `per_sample`, `vector_audit`, and `provenance` structure that the current script writes (`benchmark_memory_story_3_14.py:1478-1813`). A `grep` for `"environment"`, `"uv_lock_hash"`, or `"generator_script_hash"` in the artifact returns no matches.
  - The artifact reports `freshness.status: "skipped"` and `pass: true` (`3-14-memory-performance.json:2760`, `:2765`). With the current script’s default `--freshness-samples 30` and no LLM credentials, it would instead produce `freshness.status: "partial"` and `pass: false` (`benchmark_memory_story_3_14.py:1738-1778`).
  - **Required action:** Regenerate the artifact by running the command in `benchmark_memory_story_3_14.py:15-18` against a live PostgreSQL instance that has migrations `181` and `182` applied. Acceptance should not proceed until the regenerated artifact passes the absolute/ratio/delta gates and the cleanup audit reaches zero.

### patch

- **`GET /workspaces/{ws}/research-threads/{id}/context` indexes the embedding result without cardinality validation.**
  - `nowing_backend/app/routes/research_threads_routes.py:86` reads `query_embedding = embeddings[0]`, but the `validate_single_embedding_result` import is already present at line 28 and unused.
  - The `/memories/search` route (`memories_routes.py:96`) and the middleware (`app/agents/chat/multi_agent_chat/main_agent/middleware/memory/middleware.py:300`) already wrap `embed_texts` with `validate_single_embedding_result`.
  - **Fix:** Replace `query_embedding = embeddings[0]` with `query_embedding = validate_single_embedding_result(embeddings)`.

- **The public recall `query` inputs are not bounded to 4000 characters.**
  - AC-1 states the retrieval query is bounded to 4000 characters. The middleware enforces this in `middleware.py:131` via `_MEMORY_QUERY_MAX_CHARS`.
  - `nowing_backend/app/schemas/memory.py:73` defines `query: str = ""` with no `max_length`, and `nowing_backend/app/routes/research_threads_routes.py:44-49` defines `query: str = Query(default="", ...)` with no `max_length`.
  - **Fix:** Add `Field(default="", max_length=4000)` to `MemorySearchRequest.query` and `max_length=4000` to the research-thread `Query` parameter.

- **`_bmad-output/implementation-artifacts/deferred-work.md` is stale for the `gate.yaml` item.**
  - Line 39 of `deferred-work.md` claims `nowing_evals/src/nowing_evals/suites/memory/recall/gate.yaml` still says “deferred to Story 3.11” and needs to be changed to `3-14`.
  - In fact `gate.yaml:48-54` already uses `required_oracle_mode: score_threshold` and attributes the score-threshold fix to Story 3.14.
  - **Fix:** Update the ledger to mark that `gate.yaml` resolution as completed, and either fix the `embeddings[0] unguarded` item (see first `patch` finding) or re-defer it explicitly.

### defer

- **AC-5 live freshness harness is not run because the environment has no LLM API credentials.**
  - This is the story’s own documented escape clause (`deferred-work.md` references the “No live credentials/worker -> not done” decision).
  - The benchmark script now handles missing credentials correctly: with `--freshness-samples 30`, it sets `freshness_partial = True` and `pass = false` (`benchmark_memory_story_3_14.py:1766-1778`).
  - A rerun with real Celery/LLM credentials is required to fully satisfy AC-5.
