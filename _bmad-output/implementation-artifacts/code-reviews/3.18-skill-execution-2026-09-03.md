# Code Review — Story 3.18 Skill Execution

## Review Target

- `nowing_backend/app/services/skill_execution_service.py`
- `nowing_backend/tests/unit/services/test_skill_execution_service.py` (new)

## Diff Summary

- Added `skill_id` and `skill_slug` to workflow execution response.
- Fixed `mission.status.value` to `mission.status` (DB returns string).
- Added unit tests covering prompt skill, workflow skill, parameter escaping, and `None` parameters.
- Added E2E API tests for prompt execution, workflow dispatch, and inactive skill 400.

## Findings

### ✅ Good

1. **Bug fix is correct and minimal.**
   - `mission.status` is a SQLAlchemy column string, not an enum object, so calling `.value` raised `AttributeError`. Returning `mission.status` directly is correct.
   - Adding `skill_id`/`skill_slug` to workflow response makes the response consistent with prompt response and allows callers to correlate results.

2. **Test coverage is strong.**
   - Unit tests cover prompt execution, workflow dispatch, missing parameters, recursive template injection, and `None` parameter fallback.
   - E2E tests cover API-level prompt execution, workflow dispatch, and inactive skill 400.

3. **Template injection defense.**
   - Replacing `{` and `}` with `[` and `]` in parameter values prevents recursive placeholder expansion. This is correctly tested.

### ⚠️ Watch / Minor

1. **Conditional assertion in E2E.**
   - `if (mission.ok()) { ... }` in `projects-skills-3.18.spec.ts` is a soft assertion. If `GET /dsh/missions/{id}` returns 404, the test still passes. Should be strict.

2. **No test for `SkillExecutionService` default `dsh_service`.**
   - Unit tests always inject `dsh_service`; the default `DshMissionService()` instantiation path is not tested. Low risk because `DshMissionService` has no required constructor args.

3. **WorkspaceSkill is a MagicMock, not a real ORM instance.**
   - Unit tests use `MagicMock(spec=WorkspaceSkill)`. This is fine for service logic, but the `is_active` field is not tested through the service (the route handles this). No action needed for this diff.

## Verdict

**APPROVED** — Changes are minimal, correct, and well-tested. Minor E2E assertion softening should be addressed in a follow-up.
