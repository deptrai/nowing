## 3. What was hard / surprises — khó khăn và phát hiện muộn

### 3.1 Wallet pre-check không phải spend meter — nhầm lẫn về AD-8

Ban đầu story ghi “wallet pre-check là P0 guard against cost bleed”. Qua review phát hiện `record_token_usage` chỉ `session.add(TokenUsage(...))`, không bao giờ gọi `wallet_credit.apply_debit`. AD-8 xác định wallet-debit surface là ETL pages / premium model calls / deep-research; memory extraction cố tình không nằm trong đó (`8-7-auto-extract-spend-budget-cap.md:91-99`; `8-7-review-acceptance-auditor.md:165-167`).

- **Tác động:** phải restate AC-1, R1, module docstring, `.env.example` để wallet pre-check là *eligibility gate* (skip optional background work nếu owner không đủ tiền foreground), không phải *spend meter*. Đây là điểm tinh tế về billing semantics, nếu không rõ sẽ dẫn đến kỳ vọng sai về cost containment.
- **Bài học:** khi một gate liên quan billing, phải trace xuống `wallet_credit.apply_debit` thay vì giả định `TokenUsage` = debit.

### 3.2 Enqueue-side gate: principal drift giữa streaming caller và turn author

`finalize_assistant_message` chạy trong `anyio.CancelScope(shield=True)` trên SSE teardown path. Ban đầu định gọi `check_extract_allowed` cả wallet/anonymous tại đây, nhưng `resume_chat` authorize ở workspace level, không phải thread/author level, nên có thể một member resume thread của người khác. Nếu enqueue gate check wallet của streaming caller sẽ false-skip hoặc false-allow (`8-7-auto-extract-spend-budget-cap.md:190-191`).

- **Tác động:** quyết định D2a — enqueue-side chỉ kiểm tra workspace-scoped caps (flag + budget + rate), không lookup `User`; wallet/anonymous để `extract_from_turn` authoritative xử lý. Điều này vi phạm literal AC-7 (“disabled, over budget, rate-limited, **or wallet-insufficient**”) nhưng được ghi rõ là design deviation có test `8.7-INT-014` (`8-7-review-acceptance-auditor.md:196-214`).
- **Bài học:** defense-in-depth trên hot path phải cân bằng với chi phí extra DB query và correctness; không nên duplicate logic có principal ambiguity.

### 3.3 Rate-limit window: fixed-window vs sliding-window

`.env.example` và module docstring gọi Redis counter là “fixed-window”, nhưng code ban đầu `EXPIRE key window` trên mọi `INCR`, tạo thành sliding window. Unit test `test_record_extraction_increments_and_refreshes_ttl` còn encode sliding behavior (`8-7-review-blind-hunter.md:67-71`; `8-7-review-edge-case-hunter.md:9-29`).

- **Tác động:** sửa lại `EXPIRE` chỉ khi `count == 1`, đổi tên test thành `test_record_extraction_increments_and_sets_ttl_on_first` (`8-7-auto-extract-spend-budget-cap.md:235`).
- **Bài học:** terminology của rate-limit phải khớp implementation; “fixed-window” và “sliding-window” là hai semantics hoàn toàn khác.

### 3.4 Redis client: thiếu socket timeout, client mới mỗi call, in-memory fallback per-process

Blind Hunter review chỉ ra `_redis_client()` mở sync `redis.from_url` mới mỗi call (không cache global), không có `socket_timeout`/`socket_connect_timeout`, và in-memory fallback `_memory_hits` là module-level `defaultdict(list)` chỉ prune key đang đọc (`8-7-review-blind-hunter.md:44-63`; `8-7-review-edge-case-hunter.md:49-124`).

- **Tác động:** thêm `socket_connect_timeout=5`, `socket_timeout=5`, cache `_redis` global, và test fallback (`8-7-auto-extract-spend-budget-cap.md:238`). In-memory fallback per-process được accept nhưng cần document rõ giới hạn.
- **Bài học:** copy pattern từ `app/capabilities/core/access/rate_limit.py` phải copy cả cached client và timeout, không chỉ logic INCR/EXPIRE.

### 3.5 Budget cap / rate counter là read-then-act, không atomic

Nhiều review chỉ ra gate `SUM(cost_micros)` rồi mới gọi LLM, sau đó mới `record_extraction`/`record_token_usage`. Không có `SELECT FOR UPDATE`, serializable transaction, hay atomic `INCR`-and-check, nên concurrent turns có thể overshoot budget và rate (`8-7-review-blind-hunter.md:19-23`; `8-7-review-edge-case-hunter.md:30-69`).

- **Tác động:** deferred ra `deferred-work.md:14` vì cần AD-8 amendment và reservation ledger. Đây là vấn đề kiến trúc, không thể sửa trong story-level.
- **Bài học:** soft cap và hard cap phải phân biệt rõ trong AC và operator docs; nếu ship soft cap thì `.env.example` phải nói thẳng.

### 3.6 `TokenUsage.cost_micros` có thể = 0 khi pricing unresolvable

Nếu model pricing không register trong LiteLLM/Nowing, `_extract_cost_usd` trả `0.0`, do đó budget cap `SUM(cost_micros)` under-count spend thực tế (`8-7-review-edge-case-hunter.md:173-192`).

- **Tác động:** deferred ra `deferred-work.md:15`. Cần xử lý `None`/`unresolvable` rõ ràng — hoặc fail extraction closed hoặc dùng conservative default cost.
- **Bài học:** budget cap chỉ đúng nếu cost basis đúng; “fail open record 0” rất nguy hiểm cho cost containment.

### 3.7 Budget aggregate query thiếu composite/partial index

`TokenUsage` chỉ có single-column indexes trên `workspace_id`, `usage_type`, `user_id`; `created_at` không index, không có composite `(workspace_id, usage_type, created_at)` hay partial index `WHERE usage_type='memory_create'` (`8-7-review-edge-case-hunter.md:127-148`).

- **Tác động:** deferred; cần thêm index nếu query hot trong production. Story 8-3 cũng đã note khả năng này (`8-3-usage-credit-dashboard-new-gap.md:437`).
- **Bài học:** aggregation query trên bảng lớn nên có EXPLAIN/plan trước khi bật feature.

### 3.8 Docs/vision sync phải đụng nhiều files và translations

Việc gỡ “NotebookLM alternative”, “AI file sorting”, “Admin role” khỏi README + 4 translations + web landing + install scripts + Fumadocs tốn nhiều công hơn dự kiến (`8-10-docs-readme-vision-sync.md:25-58`).

- **Tác động:** cần audit toàn bộ bề mặt public-facing; CI drift check trở thành AC-6.
- **Bài học:** khi pivot product positioning, cần inventory forbidden phrases và drift check ngay, không để lẻ tẻ sau này.

### 3.9 Admin global model: runtime IDs âm và catalog merge

DB-backed `Connection`/`Model` là positive IDs, nhưng mọi call site global model đều expect negative runtime IDs (ví dụ `llm_bundle.py`, `llm_service.py`). Cần derive stable negative IDs từ DB IDs (`-(1_000_000 + model.id)`) và lưu `db_connection_id`/`db_model_id` trong `catalog` (`8-11-admin-ui-global-llm-model-config.md:88-95`, `D5`).

- **Tác động:** logic merge catalog phức tạp hơn dự kiến; phải đảm bảo YAML/env entries không bị DB entries overwrite.
- **Bài học:** khi thêm một persistence layer mới cho global config, phải xác định ID space và precedence rule từ đầu.

### 3.10 Refresh/pricing registration sau admin CRUD — ordering và lock

Phải đảm bảo: commit DB trước khi refresh, refresh serialize bằng `asyncio.Lock`, nếu refresh fail thì log `refresh_failed` và trả lỗi rõ ràng, nhưng DB rows đã commit (`8-11-admin-ui-global-llm-model-config.md:96-101`, `208-213`).

- **Tác động:** cần hot reload đúng; nếu refresh trước commit sẽ có catalog stale; nếu refresh fail sau commit thì process restart mới reconcile.
- **Bài học:** “no restart” requirement đòi hỏi contract rõ ràng về failure mode và reconciliation.

### 3.11 Review 8-7 phải reopen từ `done` → `review` để qua P0 human-review gate

`8-7-auto-extract-spend-budget-cap.md` ghi rõ chưa qua P0 human-review gate; `sprint-change-proposal-2026-08-01-reopen-8-7.md` đề xuất reopen story để tránh tín hiệu sprint sai (`sprint-change-proposal-2026-08-01-reopen-8-7.md:1-18`).

- **Bài học:** nên phân biệt “code complete” và “human review gate closed” trong status model để không phải revert status.

## 7. Significant discoveries that may require epic/story updates

### 7.1 Wallet pre-check là eligibility gate, không phải spend meter

- Discovery: `record_token_usage` ghi observability row, không gọi `wallet_credit.apply_debit` (`8-7-review-acceptance-auditor.md:156-159`; `8-7-auto-extract-spend-budget-cap.md:349`).
- **Cần cập nhật:** PRD §4.8/FR-31 hoặc `AD-8` nên nói rõ rằng `memory_create` cost không debit wallet; budget cap và kill-switch mới là bounds thực sự.

### 7.2 Budget cap fed bởi `TokenUsage.cost_micros` có thể = 0

- Discovery: nếu model pricing unresolvable, extraction spend không được tính vào budget cap (`8-7-review-edge-case-hunter.md:173-192`).
- **Cần cập nhật:** FR-30/FR-31 cần acceptance criteria cho “unresolvable cost” — hiện tại `token_tracking_service.py:285-288, 434-441` fail open về 0.

### 7.3 Rate-limit Redis counter dễ trở thành sliding window

- Discovery: `EXPIRE` trên mọi `INCR` tạo sliding window, trái với `.env.example` ghi “fixed-window” (`8-7-review-blind-hunter.md:67-71`).
- **Cần cập nhật:** Nếu sau này cần true fixed window, phải dùng Lua/pipeline `INCR` + conditional `EXPIRE`.

### 7.4 Global model DB-backed entries cần negative runtime IDs

- Discovery: mọi call site global model đều expect negative IDs (`8-11-admin-ui-global-llm-model-config.md:88-95`).
- **Cần cập nhật:** Architecture doc về global model ID space; conflict rule khi DB model trùng provider/model với YAML/env.

### 7.5 Admin hot reload “no restart” có failure mode rõ ràng

- Discovery: refresh fail sau commit trả 500 nhưng DB rows đã lưu; process restart reconcile (`8-11-admin-ui-global-llm-model-config.md:96-101`).
- **Cần cập nhật:** Runbook vận hành cho admin: nếu refresh fail, restart hoặc gọi `/admin/global-model-connections/refresh`.

### 7.6 Usage dashboard aggregate có thể scan hot `token_usage`

- Discovery: `token_usage` chỉ có single-column indexes; `usage/summary` và budget cap đều aggregate theo `workspace_id` + `created_at` + `usage_type` (`8-3-usage-credit-dashboard-new-gap.md:437`; `8-7-review-edge-case-hunter.md:127-148`).
- **Cần cập nhật:** Thêm composite/partial index nếu EXPLAIN trong production cho thấy sequential scan.

### 7.7 Product positioning pivot yêu cầu drift CI

- Discovery: “NotebookLM alternative”, “AI file sorting”, “Admin role” còn sót trong README, translations, web landing, install scripts (`8-10-docs-readme-vision-sync.md:25-58`).
- **Cần cập nhật:** `scripts/check-docs-drift.py` cần maintain forbidden phrases list; thêm review vào PR checklist.
