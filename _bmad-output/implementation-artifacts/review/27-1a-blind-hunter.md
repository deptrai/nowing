# Blind Hunter Review - 27.1a Web Builder Chat Mode (backend)

- `nowing_backend/app/agents/chat/multi_agent_chat/main_agent/tools/web_builder/build_web_app.py:140-154` - The tool's workspace-membership check is fail-open. The condition `if membership and not (...)` lets the call proceed when `membership` is `None`, so an invalid, missing, or removed `user_id` can still trigger generation. It also does not honor the `FULL_ACCESS` wildcard for Owners; it only checks `is_owner` or the literal `web_builder:create` string.

- `nowing_backend/app/agents/chat/multi_agent_chat/main_agent/tools/web_builder/build_web_app.py:23-29` and `build_web_app.py:95-101` - Invalid `user_id` values are only logged, then treated as `None` and used to query `WorkspaceMembership.user_id == None`, which naturally returns no row. Combined with the fail-open membership check, the tool can be invoked with a bogus or missing `user_id` and still proceed to generation.

- `nowing_backend/app/routes/web_builder_routes.py:58-64` and `web_builder_routes.py:74-79, 89-91, 112-113, 147-148` - `check_web_builder_enabled()` only consults the global `config.WEB_BUILDER_ENABLED` flag. The REST routes do not verify `Workspace.web_builder_enabled`, so a workspace on a plan where the feature is disabled can still generate and publish if the user has the `WEB_BUILDER_CREATE` permission, contradicting the per-workspace gating in the story and the tool's own workspace check.

- `nowing_backend/app/services/web_builder/deploy_service.py:43-144` - `WebAppDeployService.deploy_app()` does not fetch or check the workspace either, so publish can succeed even when `Workspace.web_builder_enabled` is `False`. The only place that enforces the workspace flag at serve time is `host_web_app` (which returns 403), but by then the public snapshot has already been written and is on disk.

- `nowing_backend/app/routes/web_builder_routes.py:383` and `nowing_backend/app/routes/__init__.py:264` - The public host route is registered as `GET /web-apps/host` on the root router, but `nowing_backend/app/services/web_builder/deploy_service.py:97` advertises `public_url = f'https://{sanitized_slug}.{self.base_domain}'` (a root path). Unless an external ingress rewrites `/` to `/web-apps/host`, every published `public_url` will 404. The story acceptance criteria and technical requirements say the URL is `https://[slug].apps.nowing.net/`, but the backend route is not root.

- `nowing_backend/app/services/web_builder/generator.py:313` and `generator.py:518` - `preview_url` is built as `f'{app_config.BACKEND_URL.rstrip('/')}/api/v1/web-builder/apps/{app_id}/preview'` and stored on the `WorkspaceApp` row. The `get_workspace_app_preview` route at `nowing_backend/app/routes/web_builder_routes.py:268-273` now requires a `workspace_id` query parameter, so the stored `preview_url` and the `complete_payload` in the streaming endpoint will hit a 400/422 from FastAPI.

- `nowing_backend/app/routes/web_builder_routes.py:292-302` - `get_workspace_app_preview` removed the fallback for missing `storage_path`. If `app_entity.storage_path` is `None` (it is nullable on `WorkspaceApp`), `project_dir` is never assigned and `project_dir.exists()` raises `NameError`, producing a 500 instead of a 404.

- `nowing_backend/app/services/web_builder/generator.py:77` and `generator.py:157` - The `language` parameter is interpolated directly into the LLM system prompt as `f'Target UI Language: {language}.'`. `WebAppBuildInput.language` and the `build_web_app` tool `language` argument are free strings with no allow-list or escaping, so a caller can pass a multi-line language string to inject instructions, bypass prompt limits, or manipulate the LLM (prompt injection through a non-prompt field).

- `nowing_backend/app/services/web_builder/generator.py:184-186` - `_call_llm_for_refinement` extracts JSON with a greedy regex (`.*`) between the first `{` and the last `}` in the response. Any nested braces, code examples, or trailing markdown get pulled into the parse, making multi-turn refinement fragile and likely to fail.

- `nowing_backend/app/services/web_builder/preview_renderer.py:19-26` - The Content-Security-Policy is intentionally broad: `default-src 'self' 'unsafe-inline' https:`, `connect-src 'self' https:`, `img-src https:`, `font-src https:`, `style-src 'self' 'unsafe-inline' https:`, and `script-src 'self' 'unsafe-inline' 'unsafe-eval' https://unpkg.com`. A generated/published app can `fetch` any HTTPS endpoint, load arbitrary images, fonts, and styles, and run inline scripts and `eval`, opening XSS and data-exfiltration paths from untrusted generated JSX.

- `nowing_backend/app/services/web_builder/preview_renderer.py:228-255` - `_sanitize_tsx_for_babel` is regex-based and context-unaware. The new type-annotation regex at `preview_renderer.py:254-255` strips any colon followed by a word character, which mangles object literals (e.g. `style={{ color: red }}` becomes `style={{ color:  }}`), JSX default props, and ordinary code, producing broken previews. The `document.cookie` replacement turns `document.cookie = 'x'` into `'' = 'x'` (a syntax error) and does not cover `window.document.cookie`, `document['cookie']`, or `window.localStorage`, leaving storage-exfiltration paths open.

- `nowing_backend/app/services/web_builder/deploy_service.py:19-34` - `disambiguate_slug` runs an unbounded `while` loop with no iteration cap and no final 63-character DNS-label guard. Under heavy slug collisions it can peg CPU and grow the candidate indefinitely. The caller in `deploy_app` then re-sanitizes and truncates to 63 at `deploy_service.py:92-96`, which can cut off a disambiguation suffix and create a fresh collision or a slug already claimed by another app.

- `nowing_backend/app/services/web_builder/deploy_service.py:119-169` - `deploy_app` writes the public HTML snapshot synchronously (`snapshot_file.write_text(...)` at `deploy_service.py:126`) and then commits inside a generic `except Exception` block (`deploy_service.py:158-161`). If the exception occurs after the file is written but before the success return, the snapshot is left on disk while the `WorkspaceApp` row is flipped to `deploy_failed`. The `with contextlib.suppress(Exception): await session.commit()` can also flush unrelated uncommitted state in the caller's session.

- `nowing_backend/app/agents/chat/multi_agent_chat/main_agent/tools/web_builder/build_web_app.py:62-69, 157, 163-170` - The tool returns `WebAppBuildOutput(...).model_dump_json()` (a JSON string) on every code path. Other chat tools such as `create_automation` return structured `dict`s. The LangChain tool result being a raw string is inconsistent with the artifact/deliverable extraction path and may cause the frontend deliverable card to fail to parse `app_id`, `preview_url`, and `public_url`.

- `nowing_backend/app/routes/web_builder_routes.py:397-409` and `web_builder_routes.py:433-437` - `host_web_app` only enforces the base domain when `config.HOSTING_BASE_DOMAIN` is set and uses a simple `endswith` check, allowing hosts like `foo.bar.apps.nowing.net` (only the first label is used as the slug). When `HOSTING_BASE_DOMAIN` is empty, the suffix check is skipped entirely and any two-part `Host` header is accepted, making the backend serve apps for arbitrary domains. It also does not re-check the global `config.WEB_BUILDER_ENABLED` or require a valid workspace for the returned snapshot.

- `nowing_backend/app/services/web_builder/generator.py:214-242` - When `build_input.app_id` is provided but the existing `WorkspaceApp.storage_path` is empty or null, `generate_project` silently ignores the requested `app_id` and creates a brand new `WorkspaceApp` with a new `app_id`. This breaks conversational refinement, leaves the original row orphaned, and causes the chat UI's `app_id` to drift.

- `nowing_backend/app/tasks/chat/streaming/flows/new_chat/chat_modes.py:94-102` and `chat_modes.py:105-128` - `resolve_chat_mode` treats any truthy `platform_metadata` value as enabled and does not enforce mutual exclusivity or boolean types, so a client sending `'web_builder_mode': 'false'` (a truthy string) or multiple mode flags at once can activate the wrong mode. `is_chat_mode_enabled`'s docstring claims a missing global gate makes the mode ungated and allowed, but the implementation defaults missing gates to `False`, contradicting its own documentation.

- `nowing_backend/app/config/__init__.py:1816` and `nowing_backend/app/db.py:1948-1950` and `nowing_backend/alembic/versions/232_add_web_builder_enabled_and_permission.py:46-48` - `WEB_BUILDER_ENABLED` defaults to `True` globally, `Workspace.web_builder_enabled` defaults to `True` for new workspaces, and the migration backfills existing rows with `server_default=true`. This turns the feature on for every workspace by default, undermining the plan gating/free-plan gating acceptance criteria and making it impossible to disable the feature for lower-tier plans without an explicit override.

- `nowing_backend/app/services/web_builder/generator.py:377-386` and `deploy_service.py:135-142` - Both `generate_project` and `deploy_app` record `TokenUsage` with hard-coded token counts (`prompt_tokens=500, completion_tokens=2000, cost_micros=15000`) and `cost_micros=0` for deploy. These are estimates, not real usage, so workspace billing and usage limits will not reflect actual LLM spend and could be gamed or under-reported.
