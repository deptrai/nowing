## Performance Assessment

### Response Time (p95)

- **Status:** ✅ PASS
- **Threshold:** PostHog init must not block first paint or LCP.
- **Actual:** `instrumentation-client.ts` defers `posthog.init` with `requestIdleCallback` / `setTimeout`. `app/global-error.tsx` now lazy-imports `posthog-js` instead of eagerly loading it.
- **Evidence:**
  - `nowing_web/instrumentation-client.ts` lines 36–103.
  - `nowing_web/app/global-error.tsx` uses `import('posthog-js')` inside `useEffect`.

- **Findings:** No synchronous PostHog JS fetch on initial load. Ad-blocker blocking the script will not delay error boundary rendering.

- **Evidence:** `lib/connector-telemetry.ts` and `lib/posthog/events.ts`.

### Resource Usage

## Quick Wins

1. **Remove `connector_title`** (done) — reduces PII surface immediately.
2. **Lazy-load `posthog-js` in `global-error.tsx`** (done) — reduces initial bundle/parse cost and prevents crashes when PostHog is disabled.

---

## Recommended Actions

### Immediate (Before release if full story is required)

1. **Scope `base-api.service.ts` error capture** — only send 5xx/network failures to PostHog; do not capture 4xx auth/validation errors.
2. **Opt-out `posthog/server.ts`** — return a no-op client when `NEXT_PUBLIC_POSTHOG_KEY` is empty and guard `instrumentation.ts`.

### Short-term (This milestone)

1. Remove dead PostHog helpers in `events.ts`.
2. Update `trackYouTubeImport` to drop raw `url` and use `connector_type: "youtube"`.
3. Update call-sites (`CreateWorkspaceDialog`, invite pages, team content) to match cleaned helper signatures.

### Long-term (Backlog)

1. Migrate outcome events to a backend product-analytics module.

---

## Monitoring Hooks

- PostHog capture errors are not application errors; monitor via `lib/posthog/events.selfcheck.ts` in CI.
- Privacy regressions can be caught by `posthog-privacy-smoke.spec.ts` with `NEXT_PUBLIC_POSTHOG_KEY` empty.
