# ATDD Checklist — 21-21-deterministic-confidence-gate-selective-micro-llm-fallback-worker

> Generated by `bmad-nowing-test-first-atdd`. Contains test descriptions (titles only) for 8 Acceptance Criteria, applying the 6 anti-pattern checklist from `docs/nowing-mutation-gate-reference.md`.

## AC-1: Schema completeness scoring & confidence gate

### Pattern 1 — Mirror Test
- [ ] `ConfidenceGate.score` should return `schema_completeness_score` in the range `[0.0, 1.0]` and `needs_enrichment` flag, not a free-form dict.
- [ ] `ConfidenceGate` should NOT call `HybridLLMRouter.ainvoke` for any record.
- [ ] A record with all 5 required fields (phone, price, district, area, title) should have `schema_completeness_score == 1.0` and `needs_enrichment == False`.

### Pattern 2 — Over-Mocking
- [ ] should handle `extract_phones_from_text` returning empty list when `primary_phone` is None.
- [ ] should handle `_split_address` returning None for address without comma/district.
- [ ] should handle `raw_data["area"]` missing or not a number.

### Pattern 3 — Edge cases
- [ ] Boundary: score exactly `0.85` should route directly to Data Plane with `needs_enrichment=False`.
- [ ] Boundary: score exactly `0.70` should mark `needs_enrichment=True`, not enqueue to `MicroExtractionWorker`.
- [ ] Boundary: score `0.699` or missing critical field should enqueue to `MicroExtractionWorker`.
- [ ] Null/empty: record with `title=None` or whitespace-only should treat title as missing.
- [ ] Null/empty: `price=0` or negative should treat price as missing.
- [ ] Concurrent: `ConfidenceGate.score` called on 100 records in sequence should produce deterministic scores.

### Pattern 4 — Arithmetic Not Asserted
- [ ] should compute `schema_completeness_score` as exactly `4/5 = 0.80` when one of five required fields is missing.
- [ ] should compute `schema_completeness_score` as exactly `0.60` when two of five required fields are missing.
- [ ] should compute score with `missing critical field` rule overriding the ratio when phone/price/district is missing.

### Pattern 5 — Error Message Not Asserted
- [ ] should raise `LeadItemValidationError` (or equivalent) with a message containing "degenerate" when all identifying fields (phone, email, domain, company_name) are empty and persistence is attempted downstream.
- [ ] should return a clear reason in `degradation_reasons` when a required parser module is missing.

### Pattern 6 — SQL (integration)
- [ ] should persist a lead row with `schema_completeness_score` and `needs_enrichment` columns populated after `ConfidenceGate` scoring (`@pytest.mark.integration`).
- [ ] should update `leads.needs_enrichment` from `True` to `False` after a later micro-LLM enrichment and re-persistence (`@pytest.mark.integration`).

## AC-2: Micro-Extraction Worker isolates snippets and routes to Tier 1

### Pattern 1 — Mirror Test
- [ ] `MicroExtractionWorker.micro_batch` should return records with only missing fields filled; valid Pass 1 fields must remain unchanged.
- [ ] `build_prompt` should return a string of at most 250 characters and must NOT contain the full listing description.
- [ ] `HybridLLMRouter.ainvoke` should be called with `task_type="micro_extraction"` and `sensitivity="public"`.

### Pattern 2 — Over-Mocking
- [ ] should handle `HybridLLMRouter.ainvoke` raising `HybridLLMError("All hybrid LLM tiers failed.")` without crashing the batch.
- [ ] should handle `HybridLLMRouter.ainvoke` returning empty JSON object `{}`.
- [ ] should handle `redact_pii` raising an exception during sensitivity detection.

### Pattern 3 — Edge cases
- [ ] Boundary: prompt length exactly 250 chars should be accepted; 251 chars should be truncated.
- [ ] Boundary: no anchor keyword (`lh`, `sđt`, `alo`, `zalo`, `không`, `chín`, etc.) in description should skip LLM call.
- [ ] Null/empty: `description` is None or empty should skip LLM call.
- [ ] Null/empty: `address` or `raw_data` is empty should produce empty prompt and skip.
- [ ] Concurrent: `asyncio.Semaphore(20)` should limit outstanding LLM calls to 20 even with 100 records.

### Pattern 4 — Arithmetic Not Asserted
- [ ] should batch at most 10 snippets per `HybridLLMRouter.ainvoke` call.
- [ ] should cap total prompt tokens per record at 200 input tokens.
- [ ] should compute `per_call_timeout = 2.0s` and `per_batch_timeout = 3.5s`.

### Pattern 5 — Error Message Not Asserted
- [ ] should log a warning containing "micro_extraction_degraded" when a single LLM call times out.
- [ ] should emit a metric with name `memory_injection_failure` or `micro_extraction_failure` and `reason=timeout|429|parse_error`.

### Pattern 6 — SQL (integration)
- [ ] should not call `HybridLLMRouter` for any record already persisted in `leads` with `schema_completeness_score >= 0.85` (`@pytest.mark.integration`).
- [ ] should persist `needs_enrichment=True` for records that failed micro-LLM extraction (`@pytest.mark.integration`).

## AC-3: Re-validate LLM output and merge only missing fields

### Pattern 1 — Mirror Test
- [ ] `parse_and_validate` should return a dict with only the keys of missing fields (phone, price, district, area).
- [ ] `parse_and_validate` should return `{}` for LLM output that does not pass Pass 1 validation.
- [ ] should not overwrite `primary_phone` when it already exists, even if LLM returns a different number.

### Pattern 2 — Over-Mocking
- [ ] should handle `extract_phones_from_text` returning empty list for LLM-suggested phone.
- [ ] should handle `_parse_price` returning None for LLM-suggested price.
- [ ] should handle `_split_address` returning None for LLM-suggested district.

### Pattern 3 — Edge cases
- [ ] Boundary: LLM returns phone starting with `1900` or `1800` should be discarded.
- [ ] Boundary: LLM returns price `0` or negative should be discarded.
- [ ] Boundary: LLM returns phone in word-number form ("không chín tám ...") and `parse_and_validate` converts it to E.164.
- [ ] Null/empty: LLM returns `null` or empty string for a missing field should not fill that field.
- [ ] Concurrent: two records in the same batch returning the same extracted phone should be handled by dedup downstream.

### Pattern 4 — Arithmetic Not Asserted
- [ ] should compute `schema_completeness_score` as exactly `4/5 = 0.80` after one successful micro-LLM fill on a record with one missing field.
- [ ] should compute `schema_completeness_score` as exactly `5/5 = 1.0` after all missing fields are filled.

### Pattern 5 — Error Message Not Asserted
- [ ] should log a warning containing "llm_output_rejected" with the rejected value and reason when validation fails.
- [ ] should return a `rejection_reasons` list in the worker result for each discarded LLM field.

### Pattern 6 — SQL (integration)
- [ ] should not update `verified_contacts` when LLM output is invalid (`@pytest.mark.integration`).
- [ ] should update `verified_contacts.phone` only after LLM-extracted phone passes E.164 validation (`@pytest.mark.integration`).

## AC-4: PII encryption, HMAC, and atomic persistence

### Pattern 1 — Mirror Test
- [ ] `LeadBatchService.ingest_batch` should encrypt phone via `VerifiedContactEncryption` before storing.
- [ ] `phone_hmac` in `verified_contacts` should be a 64-character hex string derived from E.164 phone.
- [ ] `value_hmac` should be a 64-character hex string combining phone, email, and domain.

### Pattern 2 — Over-Mocking
- [ ] should handle `VerifiedContactEncryption.encrypt` raising when input is already encrypted.
- [ ] should handle `DncComplianceService.batch_filter_leads` returning `blocked_by_dnc=True` for an otherwise valid record.
- [ ] should handle `compute_verified_contact_hmac` returning None for degenerate contacts.

### Pattern 3 — Edge cases
- [ ] Boundary: duplicate `(workspace_id, value_hmac)` in the same batch should resolve to the record with the higher `schema_completeness_score`.
- [ ] Null/empty: record with `phone=None` and `email=None` should not create a `verified_contacts` row.
- [ ] Concurrent: batch with duplicate `value_hmac` but different phones must not deadlock.

### Pattern 4 — Arithmetic Not Asserted
- [ ] should compute `phone_hmac` as exactly `HMAC_SHA256(E.164(phone), SECRET_KEY)`.
- [ ] should compute `value_hmac` as exactly `HMAC_SHA256("phone={e164}|email={norm}|domain={domain}", SECRET_KEY)`.
- [ ] should apply `func.greatest(Lead.fit_score, excluded.fit_score)` only when `fit_score` is the chosen score field.

### Pattern 5 — Error Message Not Asserted
- [ ] should raise `LeadItemValidationError` with message containing "degenerate" when a lead has no phone, email, domain, or company_name.
- [ ] should return a persistence summary with `failed_count=0` and log an error containing "persistence_error" only when `LeadBatchService` raises.

### Pattern 6 — SQL (integration)
- [ ] should execute `INSERT ... ON CONFLICT (workspace_id, value_hmac) DO UPDATE` and return `lead_id` for each accepted record (`@pytest.mark.integration`).
- [ ] should maintain `verified_contacts` unique constraint on `(workspace_id, value_hmac)` and not create duplicates (`@pytest.mark.integration`).
- [ ] should replicate to `zero_publication` and zero-cache after upsert (`@pytest.mark.integration`).

## AC-5: ≥85% bypass LLM and token spend < 4,000 per 100 records

### Pattern 1 — Mirror Test
- [ ] end-to-end run on 100 golden records should record 0 LLM calls for at least 85 records.
- [ ] `HybridLLMRouter.ainvoke` should be called at most 15 times for the low-confidence records.
- [ ] token tracking should report total prompt+completion tokens < 4,000 for the batch.

### Pattern 2 — Over-Mocking
- [ ] should handle `HybridLLMRouter.ainvoke` raising on the 3rd record and still continue to process remaining records.
- [ ] should handle `gemini_free` quota exhausted and fallback to `local_vllm_or_deepseek`.

### Pattern 3 — Edge cases
- [ ] Boundary: exactly 85 records have score >= 0.85 should still meet the bypass gate.
- [ ] Boundary: exactly 4,000 tokens should fail the budget gate (strict `< 4000`).
- [ ] Null/empty: batch with 0 records should return 0 bypass, 0 tokens.
- [ ] Concurrent: 100-record batch with 20 low-confidence records should not exceed `asyncio.Semaphore(20)`.

### Pattern 4 — Arithmetic Not Asserted
- [ ] should compute `bypass_rate` as exactly `bypass_count / 100 >= 0.85`.
- [ ] should compute `avg_tokens_per_micro_call` as exactly `total_tokens / micro_call_count < 40`.
- [ ] should compute `total_cost_micros` as exactly `0` when all calls hit `gemini_free`.

### Pattern 5 — Error Message Not Asserted
- [ ] should raise `BudgetExceededError` with message containing "token_budget_exceeded" when total tokens >= 4,000.
- [ ] should log a warning containing "token_budget_warning" at 80% of the 4,000 token cap.

### Pattern 6 — SQL (integration)
- [ ] should persist 100 lead rows and track `token_tracking_service` rows with `usage_type="hybrid_llm"` (`@pytest.mark.integration`).
- [ ] should keep total token spend per 100 records under 4,000 against a real Postgres + Redis stack (`@pytest.mark.integration`).

## AC-6: Graceful degradation on timeout / 429

### Pattern 1 — Mirror Test
- [ ] `MicroExtractionWorker.micro_batch` should return a result object with `degraded=True` and `degradation_reasons` when any call fails.
- [ ] records that degrade should keep original `schema_completeness_score` and have `needs_enrichment=True`.
- [ ] no exception should propagate to `LeadGenOrchestrator` caller.

### Pattern 2 — Over-Mocking
- [ ] should handle `HybridLLMRouter.ainvoke` raising `HybridLLMError` after one retry.
- [ ] should handle `asyncio.wait_for` raising `TimeoutError` at exactly 2.0s per call.
- [ ] should handle `asyncio.wait_for` raising `TimeoutError` at exactly 3.5s per batch.
- [ ] should handle an HTTP 429 response from `litellm`/`OpenRouter`.

### Pattern 3 — Edge cases
- [ ] Boundary: per-call timeout exactly 2.0s should degrade, not retry indefinitely.
- [ ] Boundary: per-batch timeout exactly 3.5s should degrade remaining pending calls.
- [ ] Null/empty: LLM returns empty JSON should degrade without raising.
- [ ] Concurrent: one record times out while others succeed; successful records should still be enriched.

### Pattern 4 — Arithmetic Not Asserted
- [ ] should retry exactly 1 time per record before degrading.
- [ ] should count degraded records and report `degraded_count` equal to the number of failed calls.

### Pattern 5 — Error Message Not Asserted
- [ ] should emit a log with message containing "micro_extraction_timeout" and record source_id.
- [ ] should emit a log with message containing "micro_extraction_rate_limited" and provider name.

### Pattern 6 — SQL (integration)
- [ ] should persist all records (including degraded) with correct `schema_completeness_score` and `needs_enrichment=True` (`@pytest.mark.integration`).
- [ ] should not leave partial `verified_contacts` rows for records that timed out before extraction completed (`@pytest.mark.integration`).

## AC-7: Golden Dataset — Phone F1 >= 95% without Pass 1 regression

### Pattern 1 — Mirror Test
- [ ] `GoldenDataset` should contain 100 records with fields `raw_data`, `expected_phone`, `expected_price`, `expected_district`, `expected_area`, `label`.
- [ ] `ConfidenceGate` + `MicroExtractionWorker` end-to-end should return a `PhoneF1Result` with `f1_score`, `precision`, `recall`, `pass`.
- [ ] records already passing Pass 1 should have identical `primary_phone` after the worker runs.

### Pattern 2 — Over-Mocking
- [ ] should handle `HybridLLMRouter.ainvoke` returning ambiguous phone JSON and `parse_and_validate` rejecting it.
- [ ] should handle `extract_phones_from_text` missing word-number phones in the description.

### Pattern 3 — Edge cases
- [ ] Boundary: F1 exactly 0.95 should pass the gate.
- [ ] Boundary: F1 exactly 0.949 should fail the gate.
- [ ] Null/empty: record with no phone, no price, no district should be marked `needs_enrichment=True` and not crash.
- [ ] Concurrent: running the golden dataset through `micro_batch` with concurrency 20 should still produce deterministic F1.

### Pattern 4 — Arithmetic Not Asserted
- [ ] should compute Phone F1 as exactly `2 * precision * recall / (precision + recall)`.
- [ ] should compute `bypass_rate` as exactly `bypassed_count / 100 >= 0.85`.

### Pattern 5 — Error Message Not Asserted
- [ ] should raise `GoldenDatasetError` with message containing "missing_expected_phone" if a fixture lacks an expected label.
- [ ] should return a regression report with `regression_count=0` for records that were already passing Pass 1.

### Pattern 6 — SQL (integration)
- [ ] should persist golden-dataset leads and `verified_contacts` with correct `phone_hmac` in a real Postgres instance (`@pytest.mark.integration`).
- [ ] should run end-to-end through `LeadGenOrchestrator.execute_and_persist` and verify persistence counts (`@pytest.mark.integration`).

## AC-8: LeadGenOrchestrator & EntityDeduplicationService interfaces unchanged

### Pattern 1 — Mirror Test
- [ ] `LeadGenOrchestrator.execute_multi_source_lead_gen` signature should match the original (workspace_id, query, filters, table_id, concurrency_limit, adapter_timeout_seconds, limit).
- [ ] `EntityDeduplicationService.deduplicate_leads` should still accept and return `list[NormalizedLead]`.
- [ ] public API should not expose `ConfidenceGate` or `MicroExtractionWorker` as new parameters.

### Pattern 2 — Over-Mocking
- [ ] should handle `EntityDeduplicationService.deduplicate_leads` returning an empty list after micro-LLM enrichment.
- [ ] should handle `LeadGenOrchestratorResult` missing `deduplication_summary` gracefully.

### Pattern 3 — Edge cases
- [ ] Boundary: `concurrency_limit=1` and one adapter returns 0 records should still call `ConfidenceGate` on empty list.
- [ ] Null/empty: `query=""` should not crash in `resolve_adapters_for_intent`.
- [ ] Concurrent: multiple adapters returning the same `source_id` should dedup before persistence.

### Pattern 4 — Arithmetic Not Asserted
- [ ] should compute `total_deduplicated` as exactly `len(final_leads)` after dedup.
- [ ] should compute `total_discovered` as exactly the sum of records from all adapters before dedup.

### Pattern 5 — Error Message Not Asserted
- [ ] should return `status="degraded"` with `degraded_sources` containing the failing source name.
- [ ] should return a clear error message when an adapter is not found for the query.

### Pattern 6 — SQL (integration)
- [ ] should call `EntityDeduplicationService.deduplicate_leads` before `LeadBatchService.ingest_batch` and persist the deduplicated set (`@pytest.mark.integration`).
- [ ] should not create duplicate `leads` rows for the same `(workspace_id, value_hmac)` when two adapters return the same record (`@pytest.mark.integration`).

## Cross-AC / Cross-P0 Surface Tests

### Token / Credit / Quota surfaces
- [ ] should record `token_tracking_service` row with `usage_type="hybrid_llm"` and `cost_micros=0` for `gemini_free` calls.
- [ ] should abort/alert when `HybridLLMRouter` selects a non-free tier for a micro-extraction call (cost > 0).

- [ ] should redact or mask phone numbers in the snippet before sending to `HybridLLMRouter` if PII detection would force paid tier.
- [ ] should never store raw phone in `leads` table (only encrypted in `verified_contacts`).
- [ ] should not include `value_hmac`, `phone_hmac`, or PII-derived columns in `zero_publication`.

- [ ] (integration) should update `LEADS_COLS` in `app/zero_publication.py` and verify `zero_publication` shape.
