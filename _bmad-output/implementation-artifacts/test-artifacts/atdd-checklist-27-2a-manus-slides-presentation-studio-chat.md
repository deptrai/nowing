## AC-1: Presentation Studio chat mode

### Pattern 1 — Mirror Test
- [ ] `MAIN_AGENT_NOWING_TOOL_NAMES_ORDERED` includes `"generate_presentation"` after the existing tools.
- [ ] `_MAIN_AGENT_TOOL_FACTORIES` registers `generate_presentation` with dependencies `("workspace_id", "user_id")`.
- [ ] `DELIVERABLE_TOOLS` includes `"generate_presentation"`.
- [ ] `chat_modes.py` `presentation_studio` ChatMode has `enabled_tools=["generate_presentation"]`.
- [ ] `ArtifactKind` includes `"presentation"`; `ARTIFACT_TOOL_KINDS["generate_presentation"] == "presentation"`.
- [ ] `BODY_TOOLS` in `assistant-message.tsx` maps `generate_presentation` to `GeneratePresentationToolUI`.
- [ ] `thread.tsx` welcome chips include a PPTX and a Marp slide-deck chip.
- [ ] `prompt-picker.tsx` supports `chatMode: "presentation_studio"` and slash entries `/slides pptx` and `/slides marp`.
- [ ] `new-chat/page.tsx` sets `platform_metadata.presentation_studio_mode=true` when `?mode=presentation_studio`.

### Pattern 2 — Over-Mocking
- [ ] `resolve_chat_mode` returns `default` mode when no `presentation_studio_mode` flag is present.
- [ ] `is_chat_mode_enabled` returns `False` for `presentation_studio` when `PRESENTATION_STUDIO_ENABLED=false`, even if `Workspace` is present.
- [ ] `build_main_agent_tools` with `enabled_tools=["generate_presentation"]` returns only that tool (no fallback `update_memory`/`create_automation`).
- [ ] `parse-dock-content.ts` maps `generate_presentation` to the `slides` dock tab and ignores the non-existent `build_slides`/`generate_slides` names.

### Pattern 3 — Edge cases
- [ ] Creating a thread with `presentation_studio_mode=true` while `PRESENTATION_STUDIO_ENABLED=false` returns 403.
- [ ] An existing thread keeps its `platform_metadata` when a user reopens it without the `?mode=` query string.
- [ ] A `presentation_studio` chat mode with `enabled_tools=[]` should result in no main-agent tool being available (fail-closed).
- [ ] Chip `/slides marp` should set `output_format="marp"`; chip `/slides pptx` should set `output_format="pptx"`.

### Pattern 4 — Arithmetic Not Asserted
- [ ] `GROUP_ORDER` places `presentation` immediately after `web_app` and before `report`.
- [ ] `KIND_META["video"].label` is `"Video Presentations"` while `KIND_META["presentation"].label` is `"Slide Deck"`.

### Pattern 5 — Error Message Not Asserted
- [ ] The `presentation_studio` system prompt must contain the words `generate_presentation` and `output_format`.
- [ ] A 403 on `?mode=presentation_studio` should return the message "Presentation Studio is not enabled on this workspace plan".

### Pattern 6 — SQL (integration)
- [ ] `NewChatThread.platform_metadata` persists `{"presentation_studio_mode": true}` on thread creation (`@pytest.mark.integration`).
- [ ] `GET /api/v1/threads/{id}` returns the stored `platform_metadata` unchanged for a presentation-studio thread (`@pytest.mark.integration`).

## AC-2: PPTX generation

### Pattern 1 — Mirror Test
- [ ] `PresentationStudioService.generate` (or the tool call) returns a `GeneratePresentationOutput` with `status`, `title`, `slug`, `format`, `presentation_id`, `download_url`, `slide_count`, and optional `error`/`degradation_reason`.
- [ ] Downloaded `.pptx` bytes start with the ZIP magic `PK`.
- [ ] The generated PPTX has `slide_width == Inches(13.333)` and `slide_height == Inches(7.5)` (16:9 ratio).
- [ ] At least one title slide and one content slide are present in the output deck.
- [ ] Speaker notes are populated on each slide via `slide.notes_slide.notes_text_frame.text`.

### Pattern 2 — Over-Mocking
- [ ] LLM returns invalid JSON → tool/service returns `status="validation_failed"` with a clear error and no file is written.
- [ ] `DeckSpec` contains a chart block → a `python-pptx` chart is added to the slide.
- [ ] `DeckSpec` has no chart block → the slide is generated without a chart and does not fail.
- [ ] `python-pptx` is not installed in the test environment → service returns `degradation_reason="dependency_missing"` or `status="failed"`.

### Pattern 3 — Edge cases
- [ ] Empty prompt → `status="validation_failed"`, no row, no file.
- [ ] Prompt exactly `PRESENTATION_MAX_PROMPT_CHARS` long is accepted; one character over is truncated or rejected.
- [ ] Single-slide outline (title only) still produces at least the title slide.
- [ ] Vietnamese prompt produces Vietnamese slide content and notes.

### Pattern 4 — Arithmetic Not Asserted
- [ ] `slide_width / slide_height` should be exactly `16.0 / 9.0`.
- [ ] `slide_count` in the output should equal the number of slides in the parsed `DeckSpec`.

### Pattern 5 — Error Message Not Asserted
- [ ] Malformed deck spec should return an error message containing "Could not generate a valid deck".
- [ ] A `python-pptx` write failure should log an exception whose message contains "pptx_write_failed".

### Pattern 6 — SQL (integration)
- [ ] A `SlidePresentation` row exists after PPTX generation with `format="pptx"`, `status="ready"`, and a workspace-scoped `file_path` (`@pytest.mark.integration`).
- [ ] The `SlidePresentation` row has the same `workspace_id` as the thread and a non-null `user_id` (`@pytest.mark.integration`).

## AC-3: Marp Markdown generation

### Pattern 1 — Mirror Test
- [ ] `output_format=marp` produces a `.md` file containing `---` slide separators and YAML front-matter with `theme`, `class`, and `paginate`.
- [ ] `SlidePresentation.format` is `"marp"` and `status` is `"ready"`.
- [ ] When the `marp` binary is available, `preview_url` is a valid path/URL and a rendered HTML file exists.
- [ ] `GeneratePresentationToolUI` shows the Marp-specific helper copy when no `preview_url` is present.

### Pattern 2 — Over-Mocking
- [ ] `marp` binary is missing → `preview_url` is `null`, `degradation_reason="dependency_missing"`, `status="ready"`, card shows Download `.md`.
- [ ] `marp` subprocess times out (≥30s) → service returns `degraded` with `degradation_reason="marp_timeout"` and no crash.
- [ ] `marp` subprocess exits non-zero → service returns `degraded` and logs the stderr.
- [ ] LLM returns a deck spec with no chart data → no chart markdown is injected.

### Pattern 3 — Edge cases
- [ ] `output_format` is not one of `pptx` or `marp` → tool coerces to `pptx` and logs a warning.
- [ ] The Marp markdown contains no `---` separator → `validation_failed`.
- [ ] `marp` renders HTML but the output directory is missing → service creates the directory before writing.

### Pattern 4 — Arithmetic Not Asserted
- [ ] The Marp subprocess timeout is exactly 30 seconds; a 30.1s render must be killed.
- [ ] The number of `---` separators equals `slide_count - 1`.

### Pattern 5 — Error Message Not Asserted
- [ ] Marp dependency-missing state displays the helper text "Open this file in Marp for VS Code / Marp Web."
- [ ] A Marp timeout logs a warning containing the substring `marp_render_timeout` and the `presentation_id`.

### Pattern 6 — SQL (integration)
- [ ] `SlidePresentation` row for Marp has `format="marp"`, `file_path` ending in `.md`, and `preview_url` either a path or `null` (`@pytest.mark.integration`).

## AC-4: Registry + cost

### Pattern 1 — Mirror Test
- [ ] `UsageType.PRESENTATION_GENERATE` exists and equals `"presentation_generate"`.
- [ ] `PresentationStudioService` calls `record_token_usage(..., usage_type=UsageType.PRESENTATION_GENERATE, ...)` after a successful persist.
- [ ] `record_token_usage` receives `prompt_tokens`, `completion_tokens`, `total_tokens`, `cost_micros`, `model`, `model_breakdown`, and `call_details`.
- [ ] `SlidePresentation` has a unique constraint on `(workspace_id, slug)`.
- [ ] `SlidePresentation.id` is a UUID string (length 36) and is used as the `ChatArtifact.key`.
- [ ] Generated file path is under `FILE_STORAGE_LOCAL_PATH/presentations/{workspace_id}/{presentation_id}/`.

### Pattern 2 — Over-Mocking
- [ ] `record_token_usage` raises an exception → service still returns the generated deck result and logs the failure (no crash).
- [ ] `get_agent_llm` returns a response with no usable text → `validation_failed`.
- [ ] The LLM returns a `DeckSpec` with duplicate slide titles → slug disambiguation is applied.

### Pattern 3 — Edge cases
- [ ] Two decks with the same title in the same workspace produce different `slug` values via hash suffix.
- [ ] Re-generating from the same thread creates a new `SlidePresentation` row rather than updating the existing one.
- [ ] A `file_path` outside the storage root is rejected before file write (path traversal guard).

### Pattern 4 — Arithmetic Not Asserted
- [ ] `cost_micros` equals the sum of the LLM call cost (prompt + completion) in micro-USD.
- [ ] `total_tokens` equals `prompt_tokens + completion_tokens`.
- [ ] `slide_count` in the output equals `len(DeckSpec.slides)`.

### Pattern 5 — Error Message Not Asserted
- [ ] Token usage recording failure logs a warning containing `failed_to_record_presentation_token_usage`.
- [ ] A slug collision after disambiguation still fails closed with a unique-constraint error if all suffixes are exhausted.

### Pattern 6 — SQL (integration)
- [ ] A `TokenUsage` row is inserted with `usage_type="presentation_generate"`, `workspace_id`, `user_id`, and `cost_micros > 0` (`@pytest.mark.integration`).
- [ ] `SlidePresentation` enforces `uq_slide_presentations_workspace_slug` at the database level (`@pytest.mark.integration`).

## AC-5: Auth and workspace scoping

### Pattern 1 — Mirror Test
- [ ] Every route in `presentation_routes.py` uses `require_workspace_member` (or equivalent `web_builder_routes` pattern).
- [ ] `generate_presentation` tool checks workspace membership and `PRESENTATION_STUDIO_ENABLED` before calling the service.
- [ ] `GET /api/v1/presentations/{id}` for a presentation outside the user's workspace returns 404.
- [ ] `GET /api/v1/presentations/{id}/download` for a presentation outside the user's workspace returns 404.

### Pattern 2 — Over-Mocking
- [ ] `deps["user_id"]` as a string UUID is converted to `UUID` inside the tool.
- [ ] `deps["user_id"]` is missing or invalid → `status="validation_failed"` with a permission message.
- [ ] `Workspace` row not found → `validation_failed` (tool) or 403 (route), not a server exception.

### Pattern 3 — Edge cases
- [ ] Unauthenticated request to any presentation route returns 401 before DB lookup.
- [ ] Viewer role member is denied the `generate_presentation` tool if the tool checks `WEB_BUILDER_CREATE` and the role lacks it.
- [ ] A deleted workspace still owning `SlidePresentation` rows returns 404, not 403, for all routes.

### Pattern 4 — Arithmetic Not Asserted
- [ ] Route list `GET /api/v1/presentations` returns a count equal to the number of `SlidePresentation` rows with `workspace_id == <workspace>`.

### Pattern 5 — Error Message Not Asserted
- [ ] 404 responses for cross-workspace IDs do not contain the string `"forbidden"` or any existence-leaking phrase.
- [ ] Permission-denied tool output contains "You don't have permission to generate presentations in this workspace".

### Pattern 6 — SQL (integration)
- [ ] `GET /api/v1/presentations` returns only rows where `SlidePresentation.workspace_id == <workspace_id>` (`@pytest.mark.integration`).
- [ ] `DELETE /api/v1/presentations/{id}` removes only the row and files scoped to the member's workspace (`@pytest.mark.integration`).

## AC-6: Feature gate

### Pattern 1 — Mirror Test
- [ ] `PRESENTATION_STUDIO_ENABLED=false` → `POST` to create a `presentation_studio` thread returns 403.
- [ ] `PRESENTATION_STUDIO_ENABLED=false` → `GET/POST/DELETE` under `/api/v1/presentations` return 403.
- [ ] `PRESENTATION_STUDIO_ENABLED=false` → the `generate_presentation` tool returns `status="validation_failed"` with a feature-flag message.
- [ ] `is_chat_mode_enabled(presentation_studio, workspace, config)` returns `config.PRESENTATION_STUDIO_ENABLED` (global only, no per-workspace column).

### Pattern 2 — Over-Mocking
- [ ] Missing env var for `PRESENTATION_STUDIO_ENABLED` defaults to `False`.
- [ ] `Workspace` row is `None` → `is_chat_mode_enabled` returns `False` without raising.

### Pattern 3 — Edge cases
- [ ] A thread created when the flag was `True` and later disabled still returns 403 on a new generation attempt.
- [ ] `PRESENTATION_STUDIO_ENABLED=true` but the workspace does not exist → 403, not 500.

### Pattern 4 — Arithmetic Not Asserted
- [ ] Feature-gate check completes before any DB write or LLM call (no token spend when disabled).

### Pattern 5 — Error Message Not Asserted
- [ ] 403 message contains "Presentation Studio is not enabled on this workspace plan".
- [ ] Tool `validation_failed` error contains "Presentation Studio is not enabled".

### Pattern 6 — SQL (integration)
- [ ] No `SlidePresentation` row is created when `PRESENTATION_STUDIO_ENABLED=false` (`@pytest.mark.integration`).
- [ ] No `TokenUsage` row is created when the feature flag is off (`@pytest.mark.integration`).

## Cross-AC / Cross-P0 Surface Tests

### Token / Credit / Quota surfaces
- [ ] `record_token_usage` receives `model_breakdown` with the actual model name used by `get_agent_llm`.
- [ ] `TokenUsage` has `usage_type="presentation_generate"` and `cost_micros >= 0`.
- [ ] A failed/degraded generation does not record `TokenUsage` (or records `0` with a clear `degradation_reason`).

### PII / Security surfaces
- [ ] Prompts in logs are truncated to avoid leaking full user input.
- [ ] File storage path is resolved with `Path.is_relative_to` and rejects traversal attempts like `../../../etc/passwd`.
- [ ] No `exec`, `eval`, or `shell=True` is used anywhere in `PresentationStudioService` or the Marp driver.

### Provider / Model routing surfaces
- [ ] `get_agent_llm(session, workspace_id)` is used for the LLM call, matching `WebBuilderService`.
- [ ] A non-presentation model selection still produces a valid `DeckSpec` (no provider-specific assumptions).

### SQL / Data consistency
- [ ] Alembic migration adds `slide_presentations` table with `id` (UUID), `workspace_id`, `user_id`, `title`, `slug`, `format`, `status`, `file_path`, `preview_url`, `slide_count`, `degradation_reason`, `error_message`.
- [ ] `slide_presentations` is **not** added to `app/zero_publication.py` for the MVP.
- [ ] Deleting a `Workspace` cascades `slide_presentations` if a `Workspace.slide_presentations` relationship is added; otherwise a manual `ON DELETE CASCADE` FK is configured.
