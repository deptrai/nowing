### 2.3 Architecture Spine (ARCHITECTURE-SPINE.md)

**Strengths**

- Reuse of existing AD-3/8/11.1/16/19 is correct.

**Issues / Gaps**

| # | Issue | Severity | Fix |
|---|---|---|---|
| 9 | AD-24 dedup key is `company + title + location + posted_at`, but `posted_at` may be a raw string ("Posted 4 hours ago") from ITviec or a timestamp from VietnamWorks. | Major | Add rule: `posted_at` must be normalized to UTC date before dedup. |
| 10 | AD-24 says location filter at aggregator level, but VietnamWorks `locationId` does not filter server-side. This implies fetching all pages then filtering, which could be expensive for broad queries. | Major | Add guard: `max_pages`/`max_items` limit, or fallback to source-level filtering when API supports it. |
| 11 | AD-23 TopCV cost threshold uses `$0.05/job equivalent` while the spike uses `$0.05/query`. For a search page returning 20 jobs, the per-job cost is 20× lower, but for a detail-page-per-job approach it is 20× higher. | Major | Clarify the cost model (per search page vs per detail page vs per job) in AD-23. |
| 12 | AD-25 PII redaction runs on `job_description`/`job_requirement`, but ITviec detail page may contain PII in `jd-main` outside those fields (e.g., contact info, company address). | Minor | Rule should say "all long-text fields from the source, especially `job_description`/`job_requirement`". |
| 13 | AD-26 requires ToS/legal doc in `_bmad-output/planning-artifacts/legal/`, but no such folder/file exists. | Major | Create the folder and at least a placeholder ToS review checklist. |
| 14 | AD-22..26 do not mention monitoring/alerting for the new scrapers (e.g., 403 rate, PII detection rate, aggregation degradation rate). | Minor | Add deferred or rule for observability metrics aligned with SM-12. |
