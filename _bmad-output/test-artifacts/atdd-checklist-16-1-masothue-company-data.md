- [ ] should handle `AsyncFetcher.fetch` returning 5xx → `degraded=true`, `degradation_reason=api_error`
- [ ] should handle HTML with no search result cards → `degraded=true`, `degradation_reason=empty`

### Pattern 3 (Edge cases)
- [ ] Boundary: `max_pages=0` → 0 requests, empty list, `cost_micros=0`, no degrade
- [ ] Boundary: `max_items=0` → 0 results, `cost_micros=0`
- [ ] Boundary: `max_pages=20` fetches up to 20 pages

- [ ] Null/empty: `query=None` or `query=""` → `ValidationError` or empty results
- [ ] Null/empty: `search_type` not in allowed literal → `ValidationError` with `code=VALIDATION_ERROR`
- [ ] Null/empty: `tax_code` filter set but no match → empty list
- [ ] Concurrent: two simultaneous `masothue.scrape` calls → separate `Run` rows, no shared state

### Pattern 4 (Arithmetic)

- [ ] should compute `billable_units` equal to `total_items` when `degraded=false`

### Pattern 5 (Error message)

- [ ] should handle `BillingUnit.MASOTHUE_COMPANY` not configured → default rate

### Pattern 3 (Edge cases)

- [ ] Boundary: `total_items=1` → `cost_micros=3000` (default)
- [ ] Boundary: `total_items=50` → `cost_micros=150000`
- [ ] Boundary: `degraded=true` → `cost_micros=0`, `billable_units=0`

## AC-8: Canonical entity & dedup (`entity_type="company"`, fingerprint, source `masothue`, workspace RLS)

- [ ] should create `CanonicalEntity` with `entity_type="company"`, fingerprint from normalized `tax_code` or fallback `name + address`, `search_text`
- [ ] should create `CanonicalEntitySource` with `source_name="masothue"`, `source_record_id`, `source_snapshot`

- [ ] should set `canonical_title` to company name
- [ ] should NOT store `phone`/`email` in `canonical_data` or `source_snapshot`

### Pattern 2 (Over-Mocking)
- [ ] should handle `canonical_pii.redact_canonical_data` removing phone/email from canonical data
- [ ] should handle Postgres `IntegrityError` on concurrent upsert → catch `ConcurrentUpdateError` and retry
- [ ] should handle embedding service down → still return scrape output, `embedding_status=pending`
- [ ] should handle same `source_record_id` from different sources → upsert source to matching entity

### Pattern 3 (Edge cases)
- [ ] Boundary: re-fetch same company increments `version` and updates `last_seen_at`
- [ ] Boundary: same `tax_code` from masothue and future `business.gov.vn` stays in one entity (V1 pass-through)
- [ ] Null/empty: `tax_code` missing and `name`+`address` missing → specify fallback fingerprint behavior
- [ ] Null/empty: `search_text` empty → `embedding_status` stays `pending`
- [ ] Concurrent: two simultaneous upserts of same company → one entity, no duplicate
- [ ] Data quality: Unicode NFKC normalization in `normalize()` before fingerprint

### Pattern 4 (Arithmetic)
- [ ] should compute `source_count` as number of unique source records for entity
- [ ] should increment `version` by exactly 1 on each update
- [ ] should compute fingerprint as `sha256(normalized_tax_code)[:16]` when `tax_code` present

- [ ] should raise `NowingError` with `code=DATABASE_ERROR` or `code=FORBIDDEN` when workspace isolation violated

## Cross-AC / Challenge Log — Edge cases & Failure modes

### Edge cases from `grill-me`
- [ ] `max_pages=0` or `max_items=0` → return empty list without degrading
- [ ] `max_pages=20` / `max_items=100` hard or soft limit documented
- [ ] `query=""` or `query=None` behavior specified
- [ ] Invalid `search_type` value handled
- [ ] Detail page missing `table.table-taxinfo` → skip item (do not degrade whole run unless all fail)
- [ ] Tax code missing AND `name`+`address` missing → fallback fingerprint behavior
- [ ] Concurrent upsert of same company → catch `ConcurrentUpdateError` and retry
- [ ] Re-fetch same company → update existing, merge behavior documented
- [ ] Unicode normalization for non-Vietnamese characters
- [ ] Tax code normalization (dashes vs no dashes)

### Failure modes from `grill-me`
- [ ] `scrapling.AsyncFetcher` unavailable → hard degrade, not crash
- [ ] Postgres down during canonical upsert → executor catches, does not charge
- [ ] Embedding service down → response still returns, backfill is async
- [ ] `MASOTHUE_TIMEOUT_S` is per-request
- [ ] AJAX token request timeout → fallback to GET search HTML
- [ ] Degraded run with partial items → charge successful page items only
- [ ] Cost calculation timing → after successful parse, before or after canonical upsert but not on failed pages
- [ ] Cloudflare JS challenge detection → `degradation_reason=access_blocked`
- [ ] IP ban cooldown and user notification
- [ ] V1 pass-through merge (no conflict resolution) documented
- [ ] Fingerprint collision handling (extremely rare)
- [ ] Workspace isolation verified before canonical upsert
- [ ] Adaptive backoff if masothue rate limit detected
- [ ] V1 does not need platform account rotation, documented
